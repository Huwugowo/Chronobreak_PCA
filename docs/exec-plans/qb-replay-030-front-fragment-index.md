# QB-REPLAY-030 front fragment index for replay opening

## Purpose

Open completed native recordings without making WebView2 traverse the entire fragmented MP4 before it presents frame zero. The user-visible measurement is recording selection through presented video, usable initial timeline and events, complete selected-source overlay and TAB, and initial paint. Older supported recordings keep their current playback path when their layout cannot be indexed exactly.

## Relevant planning-time architecture

`get_replay_descriptor` in `app/src-tauri/src/lib.rs` uses the owned blocking `LibraryCoordinator::read_replay` slot. `library::replay_descriptor` admits strict v2 metadata and validates the canonical video opening. The coordinator rechecks snapshot membership and root epoch after the work. `playback_server::game_video` serves the protected game URL under the existing capability, Host/Origin, method, CSP and connection limits. `playback_file::open_file` checks containment on the exact handle passed to the stream. `playback_file::file_facts` obtains the volume, file index, length and modification time from that handle.

The recorder writes `frag_keyframe`, `empty_moov`, `delay_moov` and `default_base_moof`. The existing private recorder validator in `recorder/src/finalizer/fragments.rs` proves video CFR and counts audio samples at publication. The replay index needs per-fragment byte and timing information for each track. The exporter validates and reads the canonical source and exact v2 clip frame range independently of the preview URL.

## Scope and non-goals

The change is confined to preparing the selected recording's optional index and serving the resulting byte layout through its protected game URL. Recording and publication, library scans, canonical metadata, native video controls, TAB and overlay loading, and clip export keep their existing ownership. Media recovery outcomes remain separately observable in the same complete-opening probe.

## Exploration findings

- The five gameplay sources from QB-REPLAY-029 have a front `ftyp` and empty `moov`, adjacent `moof`/`mdat` pairs and a trailing `mfra`. The video track is 60 fps with zero composition offsets. Each fragment contains video and AAC with moof-relative data offsets. The AAC edit is open-ended at rate one with a 1,024-sample priming skip, and the video edit is an open-ended identity edit. Support that original audio edit explicitly.
- The QB-REPLAY-029 remux controls established the layout cost but produced different durations. An index-only control over original bytes confirmed that WebView-family Chromium can use exact per-track fragment spans and decode times without a remux. The source `moov`, all `moof`/`mdat` bytes and the browser duration are preserved. The exact earlier and later presented video frame timestamps agree at three directed positions across the five sources. The control also indicates that the first distant seek can take longer after removing the eager scan. Record directed seek phases in the production check.
- Chromium's MOV demuxer considers a direct-reference SIDX complete when its byte references end at virtual EOF and its first offset is zero. A complete index suppresses the opening scan. When present, preserve each track's own index because Chromium can otherwise infer that track's duration from another. The source fragment's `tfdt` remains present for packet timing. [Chromium FFmpeg MOV demuxer](https://chromium.googlesource.com/chromium/third_party/ffmpeg/+/refs/heads/master/libavformat/mov.c#6580)

## Chosen design and rationale

Build an optional in-memory playback layout for a selected game. The layout consists of the original `ftyp`/`moov` bytes followed by synthesized SIDX boxes, then the original file span containing every complete `moof`/`mdat` pair. The virtual stream ends at the end of the last `mdat`. The original optional terminal `mfra` stays in the canonical file. Its `tfra` offsets refer to the original layout and the SIDX supplies the virtual index.

Use a narrow app-side reader with checked ISO BMFF box sizes and reusable scratch storage. Read the bounded initialization boxes, each bounded `moof` and paired `mdat` header, and the terminal `mfra` framing if present. Seek past encoded payloads. Require this exact top-level order and verify that the `mfra`, when present, ends at source EOF with a matching `mfro`. Accept only a unique H.264 video track and optional unique AAC track with self-contained sample entries, empty initial timing/chunk/sample tables and no external data references. Retain the original track and codec configuration bytes. Accept the native absent or open-ended identity video edit and the supported open-ended AAC identity or priming edit. Reject unknown or ambiguous offsets, encryption/auxiliary data, track types, timing transforms and unsupported layouts for indexing.

Require a verified video run starting at a sync sample in every pair. Read the `trex`, `tfhd`, `tfdt` and `trun` facts, including inherited and explicit duration, size and first-sample flags. Require moof-relative addressing with explicit run offsets, validate exact sample table size and contiguous decode time, and verify positive sample sizes and disjoint run extents contained in the paired `mdat`. Check the video origin, CFR duration, frame count and final PTS against the descriptor. Check AAC origin, timescale and final coverage against its independent exact descriptor timeline, accounting for the recognized priming edit and retaining the original timing boxes. Require AAC runs in a contiguous prefix, including finite AAC that ends while video continues. The audio SIDX covers the audio-bearing prefix and uses the original track timescale. An audio-only tail, late audio or a missing audio run followed by more audio uses original delivery unless its layout already satisfies the verified shape. A video-only recording gets one SIDX. Keep this eligibility parser independent of recorder finalization, whose private reader has different outputs and stricter publication ownership.

Serialize one version-1 SIDX per present track using the verified relative byte references, per-track decode boundaries and sync status. Put the full video index last so its first offset is zero. Calculate audio's first offset from the end of its own SIDX to the first fragment and stop its references at the last audio-bearing pair. Use checked sizing, including the 31-bit reference size, 32-bit duration, 16-bit reference count and virtual total length. Construct the entire representation or decline indexing. A declined index uses the existing protected raw URL selected by the descriptor. Exact data-plane checks must establish that audio priming and seek boundaries are the same in the original and indexed representations.

Prepare the layout inside the existing descriptor blocking job on an opened handle admitted under the coordinator's captured `ApprovedRoot`. Compare the full `FileFacts` before and after the read. Keep existing metadata and opening admission. Return the prepared value from the worker and register it only after the coordinator's selection check succeeds. Capture the approved root with the prepared value and check the current root while registering. Use a bounded in-memory registry of at most four recent representations under `MediaRoots`, with root replacement clearing its entries under the root publication lock. Each indexed descriptor adds an opaque `qb_index` query value to the existing game URL. It identifies a representation only after the normal process capability and route checks. The existing `qb_playback_session` and benchmark game-video attribution remain valid. Keep raw game URLs usable for older layouts and the existing route probe.

For an indexed range, resolve the token against its game and current approved root. Open through the existing per-request blocking path, compare the opened handle's full file facts against the prepared representation, and stream that exact handle with an independent cursor. An unknown, duplicated, evicted, or stale index query fails closed. An indexed URL always uses the same length and offsets. A pending body owns its layout and file handle through completion or cancellation. A fresh descriptor can select original delivery after an eligibility failure. Keep range parsing, HEAD/GET, 200/206/416, no-store, security headers and request/byte/cancellation telemetry on the existing paths. An indexed range is at most two spans, a slice of the immutable in-memory prefix and a bounded contiguous slice of the original file. Feed both through the existing counted streaming path. The video and audio packet bytes, `media_id`, ReplayDescriptor timeline, seek conversion and clip export source stay canonical.

## Rejected alternatives and planning decisions

- Recorder `global_sidx` would only address future recordings and needs a second pass over encoded output. Use the same app-side path for existing and future eligible captures.
- Faststart, stream-copy remux and a full-file cache add recording-sized work or storage. They also complicate exact audio and video timing. Preserve the original init and fragment bytes in the virtual stream.
- Changing duration headers was already measured and left the scan in place. A synthetic duration without verified fragment references supplies no seeking index.
- An index derived from the trailer alone cannot prove relocatable addressing, each track's exact fragment duration, or correct sample extents. Read only the structural headers and sample tables needed for those proofs.

## Performance and reliability gates

- For each indexed gameplay opening, the range trace must show the linear fragment traversal removed. Expect at most ten pre-presentation ranges on the representative sources. Compare the complete endpoint directly in matched successful trials. Account for any remaining failure separately and state when a timed-out baseline prevents a numerical paired speedup. Require a material reduction on the completed comparable recordings, with no source-selection or initial render regression.
- Bound index work by at most 65,535 references per track, at most 256 KiB each for the original init and an individual `moof`, at most 64 MiB of structural reads and a 750 ms cooperative admission budget. Check bounds during the scan and avoid all encoded payload reads and child processes. A started OS operation can outlast a cooperative limit. Build within the existing single descriptor worker, retain its permit until exit, and keep only bounded metadata in the registry and per admitted stream. The existing raw path handles already-indexed, conventional, unsupported, or over-budget inputs.
- Protect exact native timing, authorized root containment, file generation, response lengths, source preservation, and canonical export. Record cold distant seek impact separately from opening. Unexplained recovery and any failed required check remain visible at handoff.
