# Desktop preprod

Run the actual app without League, using recorded League data and labelled synthetic video. SQLite starts empty and is built by the app's normal importer. This is for UI development, replay state, seeking, saves and export. The video contains no gameplay: it cannot prove visual event alignment, A/V synchronization with gameplay or original capture quality.

From the repository root on integrated `main`, with Node/Rust/WebView2 and the staged locked media runtime available:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/preprod_launch.ps1
```

This builds and opens the current release executable. For normal Tauri frontend hot reload:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/preprod_launch.ps1 -Dev
```

Close the app before restoring the fixture with `-Reset` (combine with `-Dev` if desired). `-PrepareOnly` prepares or checks the working copy without building/opening the app. Repeated launches retain saves, clips and caches. A newly staged media runtime uses the existing `tools/media_runtime` setup; there is no system-FFmpeg fallback.

On first use or after rebuilding League data in Settings, allow roughly 1–2 minutes for Swiftplay's journal to finish indexing. The app imports it incrementally while you browse; subsequent opens reuse SQLite. Recorded gaps and incomplete query coverage remain visible.

All mutable data is under ignored `build/preprod`: `library`, `config.toml`, `app-data` and `webview2`. The launcher pins the output library, disables retention, clears frontend mocks, uses a separate WebView profile and restores its environment on exit. Keep its terminal session alive until the app closes. It refuses an unowned root, reparse paths, concurrent sessions and reset with a desktop app running. Reset only replaces the owned working library/caches; never point it at personal recordings. The checked-in files below remain the source fixture, so changes in the app affect only copies. Launching the `.exe` directly does **not** select this isolated environment; use the launcher.

## Provenance

Real sidecars come from [Huwugowo/Chronobreak_PCA, commit 7802292](https://github.com/Huwugowo/Chronobreak_PCA/commit/7802292d5fa6b9c1a59f8bcc667bd55513adc756), recorded with source `42a14671da790156d486de8c26c65908edecc593`. `source-manifest.json` preserves the archive's original manifest. The five telemetry/match/result sidecars per recording are byte-identical. `original-metadata/<id>.json` preserves each original metadata file. Identities are retained as supplied.

The original MP4s are unavailable. The prepared `library/games/<id>/video.mp4` files were authored once using the locked `queueback-ffmpeg-8.1.2-windows-x86_64-r6`: libx264 High/yuv420p, 1920x1080, exact 60 FPS, timebase 1/15360, static synthetic title card, silent AAC stereo/48kHz. All video packet PTS were checked and both outputs fully decoded. Swiftplay has 60,398 frames and one-past-last PTS 15,461,888; Practice has 7,915 frames and one-past-last PTS 2,026,240. Generated audio ends at sample PTS 48,318,384 and 6,331,968 respectively; container durations measured 1006.633333s and 131.916667s.

Prepared `metadata.json` describes these actual generated bytes. Native capture statistics, adapters and QPC evidence are removed; producer backend is `synthetic_fixture`. Original recorded time and media UUID are deliberately retained **only to associate the real telemetry with its substitute in this isolated fixture**. They are not evidence of original media content or identity. Calibrations and raw events were not changed.
